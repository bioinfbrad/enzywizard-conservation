# EnzyWizard-Conservation

EnzyWizard-Conservation is a command-line tool for calculating residue
sequence conservation from a cleaned protein sequence and a user-provided
multiple sequence alignment (MSA), and generating a detailed JSON report.
It supports three formats of MSA files (Stockholm, aligned FASTA, or A3M format). 
The tool standardizes and cleans the MSA, builds a profile hidden Markov model (HMM)
using HMMER (hmmbuild), and computes sequence conservation scores based on
HMM profile statistics. For each residue, it extracts and records: raw HMM profile score,
normalized emission probability, and normalized Shannon information content.

# example usage:

The examples below use placeholder paths such as `path/to/query.fasta`,
`path/to/alignment.sto`, and `path/to/output_dir/`; replace them with your own
cleaned query sequence file, multiple sequence alignment file, and output
directory.

Calculate conservation scores from a cleaned query FASTA file and a Stockholm
MSA. The first sequence in the MSA must match the query sequence after gap
removal.

```
enzywizard-conservation -i path/to/query.fasta -m path/to/alignment.sto -o path/to/output_dir/
```

Calculate conservation scores from a gzipped query FASTA file and a Stockholm
MSA.

```
enzywizard-conservation -i path/to/query.fasta.gz -m path/to/alignment.sto -o path/to/output_dir/
```

Calculate conservation scores from an aligned FASTA MSA.

```
enzywizard-conservation -i path/to/query.fasta -m path/to/alignment.fasta -o path/to/output_dir/
```

Calculate conservation scores from an aligned FASTA file with the `.afa`
extension.

```
enzywizard-conservation -i path/to/query.fasta -m path/to/alignment.afa -o path/to/output_dir/
```

Calculate conservation scores from a gzipped aligned FASTA MSA.

```
enzywizard-conservation -i path/to/query.fasta -m path/to/alignment.fasta.gz -o path/to/output_dir/
```

Calculate conservation scores from an A3M MSA.

```
enzywizard-conservation -i path/to/query.fasta -m path/to/alignment.a3m -o path/to/output_dir/
```

Calculate conservation scores using long option names.

```
enzywizard-conservation --input_fasta path/to/query.fasta.gz --input_msa path/to/alignment.stockholm --output_dir path/to/output_dir/
```


# input parameters:

-i, --input_fasta
Required.
Path to the input cleaned protein sequence file in FASTA format.
Supported file extensions: .fa, .fasta, .fasta.gz.
The file must contain exactly one query protein sequence.

-m, --input_msa
Required.
Path to the input multiple sequence alignment (MSA) file prepared by the user.
Supported file extensions: .sto, .stockholm, .fa, .fasta, .afa, .fasta.gz, .a3m.
The first sequence in the MSA must match the input query sequence after gap removal.

-o, --output_dir
Required.
Path to the output directory for saving the cleaned MSA, HMM profile, JSON report,
and log file.
The output directory is created automatically if it does not exist.


# output files:

The program outputs the following files into the output directory:

`{msa_name}` is derived from the input MSA file name without its extension.
`{protein_name}` is derived from the input FASTA file name without its extension.

1. A cleaned Stockholm MSA file
   - cleaned_{msa_name}.sto
     - Cleaned MSA in Stockholm format.

2. A profile HMM file
   - hmm_profile_{msa_name}.hmm
     - HMM profile generated from the cleaned Stockholm MSA.

3. A JSON report
   - conservation_report_{protein_name}.json
     - JSON report containing per-residue sequence conservation scores.

4. A log file
   - log.txt
     - Processing log containing informational messages and errors.


# output report schema:

The JSON report contains the following fields:

   - "report_type"
     - Data type: string
     - Expected value: "enzywizard_conservation"
     - Description: The field "report_type" indicates the type of report ("report": http://purl.obolibrary.org/obo/IAO_0000088) generated by the EnzyWizard-Conservation software.

   - "sequence_conservation_scores"
     - Data type: array
     - Description: The field "sequence_conservation_scores" indicates the sequence conservation scores ("sequence conservation": http://edamontology.org/operation_0448) of residues ("residue": http://purl.obolibrary.org/obo/GENO_0000782) calculated based on a hidden Markov model profile ("hidden Markov model": https://pyhmmer.readthedocs.io/en/stable/api/plan7/hmms.html; "profile": https://pyhmmer.readthedocs.io/en/stable/api/plan7/hmms.html) generated by HMMER software ("HMMER": http://hmmer.org/documentation.html).

     Each item in "sequence_conservation_scores" is an object containing:

     - "residue_index"
       - Data type: integer
       - Description: The field "residue_index" indicates the index ("index": http://purl.obolibrary.org/obo/NCIT_C25390) of the residue ("amino acid residue": http://purl.obolibrary.org/obo/GENO_0000782).

     - "residue_name"
       - Data type: string
       - Allowed values: A, C, D, E, F, G, H, I, K, L, M, N, P, Q, R, S, T, V, W, Y.
       - Description: The field "residue_name" indicates the name of the residue ("residue": http://purl.obolibrary.org/obo/GENO_0000782), using one-letter code ("one-letter code": https://iupac.qmul.ac.uk/AminoAcid/A2021.html) to represent.

     - "hmm_profile_raw_score"
       - Data type: number
       - Description: The field "hmm_profile_raw_score" indicates the raw score of the residue ("residue": http://purl.obolibrary.org/obo/GENO_0000782) obtained from the hidden Markov model profile ("hidden Markov model": https://pyhmmer.readthedocs.io/en/stable/api/plan7/hmms.html; "profile": https://pyhmmer.readthedocs.io/en/stable/api/plan7/hmms.html) generated by HMMER software ("HMMER": http://hmmer.org/documentation.html). Unit: dimensionless ("dimensionless": http://qudt.org/vocab/unit/UNITLESS).

     - "normalized_emission_probability"
       - Data type: number
       - Description: The field "normalized_emission_probability" indicates the normalized emission probability ("emission probability": https://pyhmmer.readthedocs.io/en/stable/api/plan7/hmms.html) of the residue ("residue": http://purl.obolibrary.org/obo/GENO_0000782) calculated based on the "hmm_profile_raw_score". Unit: dimensionless ("dimensionless": http://qudt.org/vocab/unit/UNITLESS).

     - "normalized_shannon_information_content"
       - Data type: number
       - Description: The field "normalized_shannon_information_content" indicates the normalized Shannon information content ("Shannon entropy": https://mathworld.wolfram.com/Entropy.html; "information content": https://www.ebsco.com/research-starters/library-and-information-science/information-content) of the residue position, calculated based on the "normalized_emission_probability". Unit: dimensionless ("dimensionless": http://qudt.org/vocab/unit/UNITLESS).



# Process:

This command processes the input sequence and MSA as follows:

1. Load input sequence
   - Read the cleaned protein sequence from the FASTA file.
   - Automatically decompress the input when the file is in .fasta.gz format.
   - Validate sequence format and characters.

2. Load input MSA
   - Read the MSA from Stockholm, aligned FASTA, or A3M format.
   - Automatically decompress the MSA when the file is in .fasta.gz format.
   - Preserve sequence alignment structure.

3. Validate MSA
   - Confirm the MSA is non-empty and properly formatted.
   - Confirm the first sequence matches the input query sequence.
   - Validate sequence characters and alignment consistency.

4. Clean and standardize MSA
   - Normalize sequence headers.
   - Remove invalid characters.
   - Remove duplicated, empty, invalid-length, or all-gap sequences.
   - Remove lowercase insertions for A3M format.
   - Ensure all sequences are compatible with Stockholm format.

5. Save cleaned MSA
   - Write the cleaned MSA into Stockholm format.
   - Add '#=GC RF' annotation so each non-gap query residue column
     is treated as a match state in HMM construction.

6. Build HMM profile
   - Run HMMER hmmbuild with '--hand' option on the cleaned MSA.
   - Generate a profile hidden Markov model representing sequence conservation.

7. Compute sequence conservation scores
   - Parse match emission raw scores from the HMM file.
   - Convert raw scores into normalized amino acid emission probabilities.
   - For each residue position:
       - extract the raw HMM profile score for the query amino acid
       - compute normalized emission probability
       - compute Shannon entropy from the full probability distribution
       - convert Shannon entropy to normalized Shannon information content

8. Save outputs
   - Generate and save a JSON report containing per-residue sequence conservation scores.


# common errors and solutions:

- "Input not found"
  - Cause: The path passed to `-i`, `--input_fasta`, `-m`, or `--input_msa` does not exist or is not a file.
  - Solution: Check the input FASTA and MSA paths and make sure both point to existing files.

- "Filename too long"
  - Cause: The input FASTA or MSA file name without extension is longer than the supported filename limit.
  - Solution: Rename the input file to a shorter name and run the command again.

- "Unsupported MSA format"
  - Cause: The MSA file extension is not supported.
  - Solution: Use Stockholm (`.sto`, `.stockholm`), aligned FASTA (`.fa`, `.fasta`, `.afa`, `.fasta.gz`), or A3M (`.a3m`) format.

- "Multiple sequences found in FASTA file"
  - Cause: The query FASTA file contains more than one sequence.
  - Solution: Use a FASTA file containing exactly one query protein sequence.

- "Invalid FASTA format"
  - Cause: A FASTA sequence line appears before the first header line.
  - Solution: Make sure the FASTA file starts with a header line beginning with `>`, followed by the sequence.

- "No header found in FASTA file"
  - Cause: The query FASTA file does not contain a FASTA header.
  - Solution: Add a FASTA header line beginning with `>` before the query sequence.

- "Empty sequence found in FASTA file"
  - Cause: The query FASTA file has a header but no sequence content.
  - Solution: Use a non-empty FASTA file containing the cleaned query protein sequence.

- "The first Stockholm MSA sequence does not match query_sequence after gap removal."
  - Cause: The first sequence in the Stockholm MSA is not the same as the input query sequence after gaps are removed.
  - Solution: Put the query sequence as the first MSA record and make sure it matches the input FASTA sequence.

- "The first aligned FASTA MSA sequence does not match query_sequence after gap removal."
  - Cause: The first sequence in the aligned FASTA MSA is not the same as the input query sequence after gaps are removed.
  - Solution: Put the query sequence as the first MSA record and make sure it matches the input FASTA sequence.

- "The first A3M MSA sequence does not match query_sequence after removing lowercase insertions and gaps."
  - Cause: The first sequence in the A3M MSA is not the same as the input query sequence after lowercase insertions and gaps are removed.
  - Solution: Put the query sequence as the first A3M record and make sure it matches the input FASTA sequence.

- "Inconsistent sequence length in Stockholm MSA"
  - Cause: At least one Stockholm MSA sequence has a different aligned length.
  - Solution: Check the MSA and make sure all aligned sequences have the same length.

- "Inconsistent sequence length in aligned FASTA MSA"
  - Cause: At least one aligned FASTA MSA sequence has a different aligned length.
  - Solution: Check the MSA and make sure all aligned sequences have the same length.

- "Inconsistent aligned length in A3M MSA"
  - Cause: At least one A3M sequence has a different aligned length after lowercase insertions are removed.
  - Solution: Check the A3M file and make sure all aligned sequences are consistent after insertion removal.

- "No valid sequences remain after cleaning."
  - Cause: All MSA records were removed during cleaning because they were empty, duplicated, invalid, all-gap, or inconsistent in length.
  - Solution: Check the MSA content and use an alignment with valid sequences matching the query-aligned length.

- "Query sequence removed during cleaning."
  - Cause: The query sequence was removed when invalid or inconsistent MSA records were filtered.
  - Solution: Make sure the first MSA sequence is valid, non-empty, not all gaps, and matches the input query sequence.

- "hmmbuild failed"
  - Cause: HMMER `hmmbuild` failed while building the HMM profile from the cleaned Stockholm MSA.
  - Solution: Confirm that HMMER is installed and available, then check the cleaned MSA and earlier messages in `log.txt`.

- "Failed to generate HMM file"
  - Cause: `hmmbuild` finished but the expected HMM file was not created or was empty.
  - Solution: Check HMMER installation, output directory permissions, and the cleaned MSA content.

- "HMM length"
  - Cause: The number of match emission rows parsed from the HMM profile does not match the query sequence length.
  - Solution: Check that the MSA first sequence matches the query sequence and that HMMER built match states from the expected columns.

- "Failed to write report JSON"
  - Cause: The JSON report could not be written to the output directory.
  - Solution: Check the output directory path and write permissions.

- MSA validation failed
  - Cause: The MSA is empty, malformed, contains invalid sequence characters, has inconsistent aligned lengths, or does not contain the query sequence as the first record.
  - Solution: Check the MSA format and content, then rerun with a valid Stockholm, aligned FASTA, or A3M file.

- HMM parsing or conservation score calculation failed
  - Cause: The HMM profile is missing expected match emission rows, has an unsupported alphabet, or contains values that cannot be parsed.
  - Solution: Review earlier messages in `log.txt`, check the cleaned MSA, and make sure HMMER generated a valid HMM profile.

- Output files are missing
  - Cause: The command failed before all output files were written, or the output directory is not the one expected.
  - Solution: Check `log.txt`, confirm the `-o` output directory, and rerun after fixing earlier errors.

- Output file names are different from expected
  - Cause: Output names use `{msa_name}` from the input MSA file name and `{protein_name}` from the input FASTA file name.
  - Solution: Check the input file names and look for `cleaned_{msa_name}.sto`, `hmm_profile_{msa_name}.hmm`, `conservation_report_{protein_name}.json`, and `log.txt` in the output directory.
